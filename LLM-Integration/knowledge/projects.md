# Projects

## StoryVerse
StoryVerse is a full-stack, AI-native platform that turns an author's written manuscript into a fully-produced 45-second cinematic book trailer — complete with visuals, camera motion, time-aligned narration, and lip-sync — then publishes it to a discovery marketplace where readers vote to greenlight production. Work that would normally take a videographer, a voice actor, and days of editing is collapsed into a self-serve pipeline that delivers a finished trailer in minutes, at price points ranging from about $0.03 to $18 per trailer. The live application is available to try at https://storyverse-production-2356.up.railway.app/.

Built end-to-end in strict TypeScript, it pairs a Node.js/Express backend with a React/Vite frontend, PostgreSQL (Drizzle ORM), Cloudflare R2 media storage, and FFmpeg for programmatic video assembly. A declarative step-runner engine orchestrates roughly 10 external AI providers — Claude and GPT-4o-mini for planning, FLUX for images, Runway, Kling, and Google Veo 3 for video, ElevenLabs for narration, and Sync Labs for lip-sync — behind a single uniform step interface, powering 8 model-agnostic pipeline tiers across a roughly 600x cost range.

Its standout engineering is a resumable, human-in-the-loop orchestration engine: because all execution state and generated artifacts are persisted in the database rather than in process memory, a long-running, multi-provider job can pause after each creative stage so the user can preview it, edit a prompt, regenerate a single asset, or swap the model for downstream steps — then resume without restarting the run or re-paying for completed work. Rayyan also built a deterministic character-consistency system that lifted locked-character coverage from about 2 of 9 scenes to 100% by moving correctness out of unreliable LLM instructions and into deterministic code, and a single-source-of-truth cost system that derives projected spend from the exact steps the runner will execute, eliminating any drift between quoted and billed cost.

## File Guardian Agent (built at XORBIX)
An agentic, local-first data-quality gatekeeper built at XORBIX that continuously watches inbound folders, validates every dropped file (CSV, JSON, or XML) against admin-defined per-column rule profiles, and routes it to good, quarantine, or review — explaining any failures in plain English via an LLM, emailing the responsible team, and surfacing every run on a live dashboard. Built in Python (Flask, watchdog, pandas/NumPy, SQLite) with a React 18 frontend and packaged as a single offline Windows executable. Rayyan rebuilt the validation core from per-cell Python loops into a chunked, vectorized pandas engine reaching about 442,000 rows/second (roughly 50x faster) with flat memory on multi-hundred-GB files, added a five-provider LLM explanation layer, and cut a profiles API endpoint from 3.1s to 0.56s by collapsing 301 N+1 queries into 3 bulk reads.

## Xorbix Document Flow (built at XORBIX)
A local-first Windows desktop document-intelligence platform built at XORBIX for manufacturing operations. Its flagship workflow turns an inbound RFQ PDF into an AI-extracted structured summary, applies a deterministic C# pricing engine, and produces an editable, exportable customer quote, with 10+ document workflows running through one pluggable pipeline. The guiding principle is "AI recommends, deterministic C# decides," so all pricing math is auditable rather than model-generated. Built in C#/.NET 8 and WPF (MVVM) with a five-provider LLM abstraction (Anthropic, OpenAI, LM Studio, and CLI providers) using strict JSON-Schema structured outputs. Rayyan cut per-document AI-extraction latency by about 95% (from 3–6 minutes to roughly 5 seconds) by moving from a multi-turn agentic loop to single-turn streaming over stdin, reduced hot-path disk I/O about 8x, and hardened the app from crash-prone to demo-stable.

## WorkAssist AI (built at XORBIX)
A Retrieval-Augmented Generation web application built at XORBIX so shop-floor operators can ask plain-English questions and get answers drawn only from approved SOPs and work instructions, each with a source citation and confidence score, declining to answer when no approved content matches. Built with a React 19 frontend and a modular Flask backend (35 REST endpoints across 13 modules), Supabase/PostgreSQL, Azure OpenAI embeddings (1,536-dimension), and Azure AI Search for hybrid keyword-plus-vector retrieval. A two-axis authorization model injects team-based filters directly into the vector search, so users can never receive answers sourced from documents their team cannot view. Rayyan built the end-to-end RAG pipeline, the access-scoped hybrid search, AI quiz generation, and a supervisor analytics dashboard that surfaces documentation gaps.

## Derse Vista — QA Engineering (at XORBIX)
